## Access (set up first)

- **Home Assistant**: `https://homeassistant.janschwarz.uk`, reached through Pangolin. Only `/api/...` is let
  through without Pangolin's sign-in (this includes `/api/websocket` and `/api/hassio_ingress/...`).
- **Token**: added by the user as a network secret on the "OneTwo3D" environment, for host
  `homeassistant.janschwarz.uk`, header `Authorization: Bearer`. It is injected by the proxy, so REST calls
  need no header. Websocket calls need the token in the auth message, which the proxy cannot supply: use the
  REST API, e.g. `/api/states`, `/api/history/period/...`, `/api/services/...`,
  `/api/config/automation/config/<id>`, `/api/config/config_entries/flow`. Statistics are websocket-only;
  use history instead, or ask the user for a websocket-capable token. Never print the token.
- **Writes**: approved by the user case by case. Always ask before writing to the inverter, Predbat, the
  integration or dashboards.
- **Predbat `apps.yaml`**: edit through Predbat's own editor via ingress (`/api/hassio_ingress/...`,
  add-on `6adb4f0d_predbat`, page `apps_editor`, POST field `apps_content`). It writes a backup
  `apps.yaml.backup` and Predbat restarts by itself.
- **Files under `/homeassistant`**: write through the File editor add-on (`core_configurator`), via
  ingress `api/save`.
- **Tablet dashboard**: repo `OneTwo3D/ha-energy-dashboard`, deployed with `tools/deploy.py`. It normally
  needs the user's SSH tunnel; the previous session used a copy that went through the HA ingress.
- **Frigate/unraid** (192.168.1.210) is not reachable from a cloud session.
